# TicketHelp — фронтенд

Vite + React + Tailwind. Два экрана в одном приложении, переключаются
кнопками «Оператор» / «Пользователь» в правом верхнем углу (это демо-
переключатель для показа обеих сторон продукта, не часть самого продукта).

Работает поверх бэкенда TicketHelp (FastAPI, см. корневой `README.md`) —
все заявки хранятся в SQLite бэкенда, моков в интерфейсе нет.

## Команды

```bash
npm install
npm run dev       # дев-сервер, http://localhost:5173
npm run build      # прод-сборка в папку dist
npm run preview    # предпросмотр собранной сборки
```

Перед запуском убедитесь, что бэкенд поднят на `http://localhost:8000` (см.
корневой README). Если бэкенд слушает другой адрес — скопируйте
`.env.example` в `.env` и поменяйте `VITE_API_BASE_URL`.

## Структура

```
src/
  api/             клиент к FastAPI-бэкенду (client.js) и адаптер ответа под форму карточек (normalize.js)
  data/            константы (статусы/приоритеты) и дерево диалога чат-бота
  context/         TicketsContext — общее состояние заявок, синхронизированное с бэкендом
  components/
    operator/      Kanban-доска, детальная карточка заявки, аналитика, база знаний, API-панель
    user/          чат пользователя с разветвлением вопросов; любое сообщение уходит в /api/tickets/ingest
```

## Продуктовая логика

Это интерфейс второй линии поддержки: ИИ никогда не отвечает пользователю от
своего имени. Чат-бот и бэкенд лишь декомпозируют обращение на заявки,
определяют категорию/приоритет и готовят рекомендованный ответ — оператор
обязательно проверяет и отправляет ответ сам (кнопка «Вставить
рекомендованный ответ» в карточке заявки).
